# APT repository (`https://astreele.github.io/opencode-android`)

This directory holds the *client-side* files for the Termux package-manager
install path; the published repository itself lives on the `gh-pages` branch
(served by GitHub Pages) and is regenerated by
`.github/workflows/apt-repo.yml` on every `*-android` release.

| File | Purpose |
|---|---|
| `opencode-android.list` | apt source entry, installed by `install.sh` to `$PREFIX/etc/apt/sources.list.d/` |
| `opencode-android.gpg` | binary (dearmored) repo signing key, installed to `$PREFIX/etc/apt/trusted.gpg.d/` |
| `opencode-android.asc` | same key, armored — for inspection (`gpg --show-keys`) |

## Published layout (gh-pages branch)

```
pool/main/opencode2/*.deb                        # kept: newest 4 per package
dists/stable/main/binary-aarch64/{Packages,Packages.gz,Packages.xz}
dists/stable/{Release,InRelease,Release.gpg}
opencode-android.gpg                             # copy of the key above
```

## Regenerating locally

```sh
make apt-repo REPO_DIR=apt-repo OUT=out   # unsigned preview (adds --no-sign? see script)
bash scripts/apt-repo.sh --help
```

`scripts/apt-repo.sh` only needs `dpkg-deb`, `gzip`, `xz`, coreutils and
(optionally) `gpg` for signing — no `dpkg-dev`/`apt-ftparchive`.

## Key rotation

1. Generate a replacement key, export it over these two files.
2. Publish it to the `gh-pages` root (the workflow copies `--key-file` on
   every run, so the next release picks it up).
3. Re-run `install.sh` (or re-download the `.gpg`) on devices — then switch
   the `APT_GPG_PRIVATE_KEY` secret to the new private key.
